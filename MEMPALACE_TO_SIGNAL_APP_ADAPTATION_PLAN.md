# MemPalace To Signal App Adaptation Plan

Date: 2026-04-07

## Status

This document defines the clean fit for MemPalace around the MT-07 Live Signals app.

MemPalace should be treated as a local build-memory and helper-context layer, not as a live field-truth component.

This is an adaptation plan, not an activation note.

## Governing Law

Let memory preserve the craft around the instrument; do not let memory impersonate the instrument.

Companion line:

MemPalace may preserve doctrine, checkpoints, and design memory.  
MT-07 remains sovereign over visible field state, metric meaning, and audit truth.

## Why This Fits

The Signal app already has its own governed path:

`text -> normalization -> incident form -> event geography -> incident identity -> category -> escalation pressure -> field authority -> visibility -> recovery / thin-sample honesty -> metrics -> audit`

MemPalace is a better fit for:
- memory
- retrieval
- doctrine continuity
- checkpoint recall
- build-history lookup
- helper-lane context

It is not a good fit for:
- live event truth
- visibility gating
- scoring doctrine execution
- operator-facing classification
- corroboration authority

## Adopt Now

Use MemPalace only as a local build-memory and helper-context archive.

Good Phase 1 uses:
- repo doctrine and governance notes
- checkpoints and reports
- design plans and integration notes
- build-memory and decision history
- local documentation and KB material

Suggested first rooms:
- `signal-app / doctrine`
- `signal-app / checkpoints`
- `signal-app / integrations`
- `signal-app / runtime-notes`
- `signal-app / lineage`
- `signal-app / helper-lane`

## Adopt Later

Only after a narrow Phase 1 proves useful:
- helper-lane retrieval for prior decisions or checkpoint continuity
- operator-reviewed helper summaries backed by recalled docs
- controlled human-approved memory writes like:
  - `store this checkpoint note`
  - `save this doctrine line`
  - `file this report into signal-app/checkpoints`

If later phases happen, keep them:
- read-first
- human-approved for writes
- clearly marked as recalled context
- outside the MT-07 truth path

## Docs Only

MemPalace is a good home for:
- README and adjacent governance docs
- checkpoint notes
- adaptation plans
- lineage notes
- selected exported design chats

Store curated materials, not raw exhaust.

Preferred first ingest sources:
- `README.md`
- `CLAUDE_CODE_SIGNAL_APP_INTEGRATION_PLAN.md`
- `CLAUDE_AGENT_SDK_SIGNAL_APP_EMBED_PLAN.md`
- `CLAUDE_AGENT_SDK_PHASE1_REPO_SKELETON.md`
- `MT07_TONE_LAYER_CHECKPOINT_2026-04-02.md`
- wording checkpoints
- escalation checkpoints
- geography checkpoints
- normalization cleanup reports
- selected design notes that explain boundaries

## Never / Not For Runtime

MemPalace must not become a shadow truth engine.

Do not use it for:
- deciding visibility
- deciding event classification
- deciding field authority
- deciding escalation state
- deciding tape ranking
- counting as a source or source family
- acting as corroboration
- upgrading weak evidence into visible field truth
- writing into `/api/dashboard`
- writing into `/api/events`
- writing into `/api/explain/metric/:key`
- writing into snapshot bundles
- writing into processed truth tables
- overrule current live state with old notes
- treat recalled context as stronger than governed runtime output

Also do not ingest:
- `.env`
- API tokens
- credentials
- raw secrets
- entire volatile runtime directories
- raw event DB tables as canonical memory
- endless raw traces or uncurated volatile dumps

## MCP Boundary Rules

If MemPalace is exposed through MCP, keep the same law as the Claude helper plans.

### Rule 1 — Read-first only

Phase 1 should be retrieval-first.

Allow:
- search
- recall
- summarize retrieved docs
- fetch prior checkpoint context
- compare current note against prior doctrine

Do not allow:
- automatic memory writes from live board routes
- automatic mutation of app outputs
- hidden background ingestion of runtime truth

### Rule 2 — Human-approved writes

If writes are enabled later, only allow them through explicit human-approved actions.

### Rule 3 — Keep memory separate from signal truth

MemPalace results must stay outside:
- `/api/dashboard`
- `/api/events`
- `/api/explain/metric/:key`
- visibility and scoring paths

Memory may inform helper notes.  
Memory may not become field truth.

### Rule 4 — Keep retrieval visibly advisory

Any future UI use must be marked:
- advisory
- recalled context
- operator-reviewed
- not live signal evidence

### Rule 5 — Prefer curated memory over raw exhaust

Store:
- checkpoint reports
- doctrine files
- plans
- reviewed notes

Do not store:
- endless raw traces
- repetitive helper chatter
- uncurated volatile dumps

## Safe Prompt Examples

- `Search Signal App checkpoints for the last tone-layer anchor line.`
- `Summarize what changed in escalation checkpoints over the last two reports.`
- `Find the current doctrine lines for Claude boundaries in this repo.`
- `Compare the event geography checkpoint with the normalization cleanup report.`

## Unsafe Prompt Examples

These should be blocked or refused by policy:
- `Use memory to decide whether this cluster should be visible.`
- `Promote this event because it matches prior doctrine.`
- `Rewrite current board truth based on old checkpoints.`
- `Classify this live incident from memory only.`
- `Auto-publish a helper summary into the live dashboard.`

## Phase 0 Sandbox Test Path

If we test MemPalace, keep the first pass narrow.

1. Install MemPalace separately from the app runtime.
2. Use raw/verbatim storage first.
3. Do not enable auto-save hooks at the start.
4. Ingest only curated doctrine and checkpoint docs.
5. Test retrieval against a few known boundary questions.
6. Confirm it helps craft memory without affecting field truth.

AAAK is interesting, but it should stay out of the first pass while it remains experimental and lossy relative to raw mode.

## Stop Conditions

Stop or narrow the memory layer if:
- it starts to sound like a hidden truth source
- it is used to overrule current live field state
- memory retrieval gets mistaken for corroboration
- the stored corpus becomes too noisy to be trustworthy
- operators confuse recalled doctrine with current runtime evidence

## Verdict

PASS

Why:
- MemPalace fits well as build-memory and helper-context
- it does not belong in the MT-07 truth path
- the wing/room model maps naturally to doctrine and checkpoint history
- Phase 1 can stay narrow, curated, and local-first

## Anchor

Let memory preserve the craft around the instrument; do not let memory impersonate the instrument.
