# Negotiation Geometry Matrix Fit Plan

Date: 2026-04-08

## Status

This document defines the clean fit for a negotiation-geometry or structural-read surface around the MT-07 Live Signals app.

The purpose is not to forecast outcomes. The purpose is to compress bargaining structure into a disciplined, non-predictive read.

This is a fit plan, not an activation note.

## Governing Law

Map the structure first; do not force the conclusion early.

Companion lines:

Structural Read maps what the field is made of; Tree of Relief resolves what the present window became.

Structure first. Probability later, if ever.

## Why This Fits

The Signal app already operates as a governed, non-predictive field instrument.

Its active path remains:

`text -> normalization -> incident form -> event geography -> incident identity -> category -> escalation pressure -> field authority -> visibility -> recovery / thin-sample honesty -> metrics -> audit`

That means the app is already built to answer:
- what is active
- what is load-bearing
- what earned appearance
- what was held out
- what remains unresolved

A Structural Read extends that logic cleanly.

It asks:
- what is the current field mainly made of?
- what is load-bearing?
- what is visible texture rather than decisive structure?
- what is being held out?
- what is thin because reality is thin versus thin because authority failed?
- what is active now without forecasting what comes next?

## Structural Read vs. Tree Of Relief

Keep the two voices distinct.

### Structural Read

Structural Read is the analytical discipline layer.

It should answer:
- what formed structurally
- what is load-bearing
- what constrains movement
- what pressure sits underneath visible appearance
- what remains unresolved in the present field

### Tree Of Relief

Tree of Relief is the humane resolve layer.

It should answer:
- what this window became
- what held
- what resolves
- what remains open

The pair should remain:
- one voice for method
- one voice for meaning

## Adopt Now

Adopt the idea only as a secondary or drawer-level structural surface.

Good Phase 1 roles:
- diplomacy-heavy explain block
- secondary panel near notes / Tree of Relief
- operator-facing structural compression for negotiation-rich windows
- helper-lane analytical summary later, if needed

The cleanest first use is:
- negotiation geometry
- concession structure
- tradable vs hard-collision mapping
- load-bearing vs decorative demand compression

## Adopt Later

Later, after the concept proves useful, consider:
- a broader `Structural Read` block for non-negotiation windows
- richer bargaining matrices for diplomacy-heavy event clusters
- helper-lane summaries that compare multiple structural reads across recent windows

Only promote it if it:
- stays non-predictive
- stays evidence-bounded
- helps operators orient without creating authority confusion

## Never

Do not let a negotiation geometry surface:
- forecast settlement
- assign future probabilities
- speak as if it knows the end state
- replace incident truth
- replace field authority
- replace visibility or scoring
- override held-out logic
- publish as tape truth

Do not use wording that implies:
- certainty about what will happen
- hidden diplomatic knowledge
- probabilistic forecasting dressed up as structure

## Best Placement

Do not place this in the main metric row.

Best first homes:
- under `Volatility Notes`
- beside `Tree of Relief`
- inside an explain drawer
- in a clearly secondary analysis panel

This should feel like a structural note, not a core board metric.

## Required Basis

Only emit a structural read when the window has enough basis to justify compression.

Good basis signals:
- diplomacy is materially present
- multiple corroborated negotiation or bargaining items are visible
- coherence is sufficient to support compression
- the field has enough position-density to distinguish:
  - core demands
  - tradable items
  - hard collisions
  - unresolved pressure

Suppress or soften the feature when:
- the sample is thin or empty
- held-out pressure is too large relative to visible material
- the field is too noisy or fragmented
- the window is mostly incident churn without coherent bargaining shape

If basis is too weak, say so directly:

`Insufficient structural basis for negotiation geometry in this window.`

## Suggested V1 Output Shape

Keep the first form compact and analytical.

### Structural Read

- `Active domain`
- `Load-bearing factors`
- `Constraint factors`
- `Held-out pressure`
- `Current structural state`
- `Open edge`

### Negotiation Geometry

For diplomacy-heavy windows, a second compact form can be used:

- `Core asks`
- `Tradable zone`
- `Hard collision points`
- `Interim corridor`

### Optional Matrix Form

If a side-by-side matrix is used, keep it descriptive:

- `Position / ask`
- `Observed counter-position`
- `Overlap corridor`
- `Collision level`

Avoid “probable outcome” framing.

## Allowed Wording

Prefer:
- structural read
- negotiation geometry
- bargaining geometry
- feasibility band
- overlap corridor
- tradable zone
- hard collision
- load-bearing factor
- constraint factor
- interim corridor
- current structural state

Good example phrases:
- `This window shows a bargaining field with a narrow overlap corridor.`
- `Several demands appear load-bearing, while others function more like anchor terms.`
- `The visible surface suggests a tradable core surrounded by harder collision points.`

## Forbidden Predictive Wording

Avoid:
- likely outcome
- most probable compromise
- likely endgame
- chance of settlement
- will survive
- will concede
- forecast
- probability
- best estimate of the deal

Replace them with:
- current overlap corridor
- current structural state
- most translatable under present pressure
- current hard collision level
- observed bargaining geometry

## Example Output

### Thin / No-Call Window

```text
Structural Read

Active domain: sparse visible field with high held-out pressure
Load-bearing factors: strict gating, thin sample, low cross-source authority
Constraint factors: weak cluster precheck, missing location, low support breadth
Held-out pressure: activity exists underneath, but not enough earned appearance
Current structural state: observationally thin, directionally unresolved
Open edge: the field is active, but this window does not yet justify a broader claim
```

### Diplomacy-Heavy Window

```text
Negotiation Geometry

Core asks: sanctions relief, asset access, survival guarantees
Tradable zone: shipping procedures, staged economic relief, de-escalation wording
Hard collision points: unrestricted enrichment, formal reparations, total withdrawal language
Interim corridor: partial relief in exchange for reduced escalation and bounded monitoring
```

## Minimal Implementation Order

1. define the doctrine and wording boundary
2. decide where the first structural surface should live
3. define minimum evidence basis
4. build a compact structural-read payload shape
5. test it first on diplomacy-heavy windows
6. confirm it helps orientation without sounding predictive
7. only then consider broader use

## Stop Conditions

Stop or narrow the feature if:
- it starts sounding like a forecast
- it outruns the evidence basis in thin windows
- operators confuse it with settlement prediction
- it starts competing with Tree of Relief instead of complementing it
- it pressures the app toward stronger claims than the current field justifies

PASS

Why:

- it extends existing MT-07 logic rather than fighting it
- it gives the method layer a lawful structural voice
- it pairs naturally with Tree of Relief without replacing it
