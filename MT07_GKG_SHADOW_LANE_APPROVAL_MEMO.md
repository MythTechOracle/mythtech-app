## Decision

The **GKG Shadow Lane Fit Plan** is approved at the **fit and doctrine layer**.

This approval is granted because the plan places GKG in the correct role: a **shadow context lane** around the MT-07 event body, not an author of event truth. Under the plan's governing law, GKG may enrich themes, entities, framing, and audit context, while MT-07 remains sovereign over visibility, scoring, corroboration, escalation pressure, field authority, and operator-facing truth.

This is the correct architectural boundary.

---

## Approval Basis

The current Signal path is already governed as:

`text -> normalization -> incident form -> event geography -> incident identity -> category -> escalation pressure -> field authority -> visibility -> recovery / thin-sample honesty -> metrics -> audit`

The plan fits because GKG-style material is primarily:

- text-derived context
- theme and entity enrichment
- framing and tone metadata
- relation hints around what event language is doing

That means it belongs best as a **shadow layer around the event body**, not as the event body itself.

The plan also correctly states that GKG must not function as:

- a visibility governor
- a tape-card authority
- an independent corroboration source
- a replacement for event identity or event geography

This preserves MT-07 sovereignty and keeps descriptive context from mutating into runtime truth.

---

## Risk Statement

The primary risk is **authority creep**.

Without a sealed contract layer, a shadow lane can drift into:

- entity spam
- theme inflation
- source-family churn
- location drift
- quote theater
- framing drama without event authority
- weak-cluster inflation
- corroboration confusion
- sentiment theater

These are not cosmetic failures. They are the exact mechanisms by which contextual material begins to impersonate event truth.

A second risk is **operator misreading**. If GKG-derived density is mistaken for corroboration, then entity volume can appear to be certainty, tone can appear to be authority, and quote concentration can appear to be field truth.

A third risk is **premature promotion**. The plan is correct to permit later promotion only after repeated live-cycle proof that GKG improves audit clarity and cluster interpretation without distorting truth law or inflating thin samples into false confidence.

---

## Required Amendments Before Build Action

Before any build activation, connector wiring, or operator-facing rollout, the following contract layer must be explicit.

### 1. Shadow Admission Contract

Every GKG-side object must declare itself as subordinate context and not event authority.

At minimum, the lane should encode:

- source provenance
- source lane identity
- parser or extraction version
- bound event or cluster reference
- confidence
- shadow-only status
- non-corroborative status

### 2. Tight Field Semantics

The following fields must be governed by narrow semantics and controlled value sets:

- `framing_signals`
- `relation_hints`
- `tone_support`

These fields should not remain open drift surfaces.

### 3. Promotion Gates and Thresholds

Selective promotion must require named and measurable proof, including:

- improvement in audit clarity
- improvement in cluster interpretation
- no increase in false corroboration pressure
- no measurable inflation of weak or thin samples
- no distortion of visibility or field-authority logic

### 4. Machine Checks and Provenance Rules

The plan's identified risks should become enforcement checks, not only review notes.

Required classes of checks include:

- duplicate or overlap controls against existing GDELT DOC intake
- source-family concentration checks
- location divergence checks
- quote-density limits
- provenance preservation through every handoff

### 5. Operator Wording Law

Every operator-facing surface using GKG context must clearly state that the lane is:

- context support only
- not event authority
- not corroboration
- not visibility logic

This wording should be stable across helper, audit, and explain surfaces.
